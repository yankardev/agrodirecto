# Guía de contribución

## Ramas

1. Actualizar `develop`.
2. Crear una rama desde `develop`.
3. Realizar cambios pequeños y coherentes.
4. Hacer commits con Conventional Commits.
5. Subir la rama.
6. Crear Pull Request hacia `develop`.
7. Solicitar revisión de otro integrante.

## Nombres de ramas

- `feature/auth-login`
- `feature/catalog-productos`
- `feature/order-checkout`
- `feature/frontend-catalog`
- `fix/stock-validation`
- `docs/architecture`

## Reglas

- No subir contraseñas ni secretos.
- No subir `target/`, `node_modules/` ni `dist/`.
- No hacer push directo a `main`.
- Todo cambio funcional debe llegar por Pull Request.
- Antes de solicitar revisión, comprobar que el proyecto compila y las pruebas pasan.
